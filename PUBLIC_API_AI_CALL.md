# ИИ-звонок — итог разговора

Пациент не ответил на напоминание о визите, и портал завёл в CRM (LPTracker) лид
на шаге «Обзвон роботом». Робот звонит, а CRM по итогу разговора сообщает нам,
**чем кончилось**. Портал ставит отметку в МИС: подтверждает или отменяет визит.
Без этого вызова звонок ничего не меняет — визит остаётся активным, и о неявке
узнают в день приёма.

Ключ обмена — `appointment_id`, номер визита в МИС. Он приходит в CRM в
одноимённом поле лида.

---

## Эндпоинт

```
POST https://wiki.medcentralfa.ru/api/public/v1/ai-call/result
```

| Заголовок | Обяз. | Значение |
|---|---|---|
| `X-Api-Key` | да | API-ключ с правом `ai-call:result`, выдаётся в Администрирование → Интеграции |
| `Content-Type` | да | `application/json` |

Ключ можно ограничить списком IP — пришлите адреса, с которых будете
обращаться. Каждое обращение пишется в журнал портала.

---

## Поля

| Поле | Ключ | Обяз. | Формат |
|---|---|---|---|
| Номер визита в МИС | `appointment_id` | да | число — тот же, что пришёл в лиде. Принимается также `appointmentId`, `visit_id`, `visitId` |
| Итог разговора | `result` | да | код или название шага воронки, см. ниже. Принимается также `status`, `funnel_step`, `funnelStep` |
| Комментарий | `comment` | нет | что сказал человек; при отмене дописывается в карточку визита в МИС. Принимается также `note` |
| Номер лида | `lead_id` | нет | число. Принимается также `leadId` |
| ФИО пациента | `patient_name` | нет | строка |
| Время визита | `visit_at` | нет | `ГГГГ-ММ-ДД ЧЧ:ММ:СС` |
| Клиника | `clinic` | нет | строка |

Портал действует только по `appointment_id`. Остальные поля сохраняются вместе
с телом запроса, чтобы в спорном случае было видно, о каком визите шла речь.

---

## Значения `result`

Можно присылать наш код или название вашего шага воронки — регистр не важен.

| Код | Принимаются также | Что происходит в МИС |
|---|---|---|
| `confirmed` | `подтвердил`, `подтверждён`, `confirm` | **подтверждение визита** |
| `cancelled` | `отменил`, `отмена`, `отказ`, `AI · Отказ`, `refused` | **отмена визита** |
| `no_answer` | `не дозвонились`, `AI · Не дозвонились`, `нет ответа` | только запись в журнал |
| `voicemail` | `автоответчик`, `AI · Автоответчик` | только запись в журнал |
| `hangup` | `бросил трубку`, `сбросил` | только запись в журнал |
| `callback` | `перезвонить`, `AI · Перезвонить`, `позвонить позже` | только запись в журнал |
| `operator` | `перевод на КЦ`, `нужна проверка` | только запись в журнал |
| `unclear` | `разговор без результата`, `AI · Разговор без результата` | только запись в журнал |

Незнакомое значение не отвергается: портал запишет его как `other` и сохранит
тело целиком.

Если список изменится, актуальный всегда можно получить запросом:

```
GET https://wiki.medcentralfa.ru/api/public/v1/ai-call/results
X-Api-Key: wk_live_...
```

```json
{
  "ok": true,
  "results": [
    { "code": "confirmed", "aliases": ["confirmed", "confirm", "подтвердил", "..."], "mis": "подтверждение визита" },
    { "code": "no_answer", "aliases": ["no_answer", "не дозвонились", "..."], "mis": "только запись в журнал" }
  ]
}
```

## Пример

```bash
curl -X POST https://wiki.medcentralfa.ru/api/public/v1/ai-call/result \
  -H "X-Api-Key: wk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "appointment_id": 4412308,
    "result": "confirmed",
    "lead_id": 10035871,
    "patient_name": "Иванов Иван Иванович",
    "visit_at": "2026-09-22 10:00:00",
    "clinic": "Альфа Линия",
    "comment": "Сказал, что придёт"
  }'
```

## Ответы

**200** — итог принят:

```json
{
  "ok": true,
  "requestId": "3f2b…",
  "result": "confirmed",
  "mis": "confirmed",
  "misError": null,
  "repeated": false
}
```

| Поле | Значение |
|---|---|
| `result` | как портал понял присланный исход |
| `mis` | `confirmed` / `cancelled` — отметка в МИС поставлена; `none` — исход визита не меняет или менять нечего; `failed` — МИС отказала |
| `misError` | причина, если `mis` равно `failed` или `none` по состоянию визита |
| `repeated` | `true` — этот итог уже был принят раньше, повторно ничего не делалось |

Повторная отправка того же итога безопасна: портал не подтверждает визит второй
раз и не отменяет уже отменённое. Перед отменой портал проверяет визит в МИС:
если приём уже состоялся или визит отменён, отмены не будет — ответ придёт с
`"mis": "none"` и пояснением в `misError`.

| Код | `error` | Когда |
|---|---|---|
| 400 | `bad_request` | нет `appointment_id` или `result` |
| 401 / 403 | — | ключ не передан, неверен, отозван, нет права `ai-call:result` или запрос не с разрешённого IP |
| 404 | `not_found` | визита с таким номером портал не знает |
| 429 | `rate_limited` | слишком много запросов; повторите через число секунд из заголовка `Retry-After` |
| 500 | `internal_error` | ошибка на нашей стороне; повторите через несколько минут |

```json
{ "ok": false, "error": "not_found", "message": "Визит не найден" }
```
