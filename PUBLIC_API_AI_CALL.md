# ИИ-звонок пациенту, не ответившему на напоминание

Документ для программиста на стороне CRM (LPTracker). Описывает обе половины
обмена: что портал «Альфа-Вики» кладёт в CRM и что портал ждёт назад, когда
разговор состоялся.

Портал не звонит и не знает сценария разговора. Он отвечает на один вопрос —
**кому звонить** — и принимает один ответ — **чем кончилось**.

---

## Когда это происходит

1. Пациент записывается на приём. Портал узнаёт об этом от МИС Renovatio и
   планирует напоминание на время «визит минус N» (обычно за сутки).
2. Напоминание уходит пациенту в Telegram, MAX или SMS. Под сообщением две
   кнопки: «Подтверждаю» и «Отменить запись»; нажатие сразу уходит в МИС.
3. Через настроенное время **после доставки напоминания** портал смотрит, ответил
   ли человек. Ответил — на этом всё.
4. Не ответил — портал заводит в CRM контакт и лид на шаге «Обзвон роботом».
   Звонит робот.
5. По итогу разговора CRM вызывает метод портала из части 2, и портал ставит
   отметку в МИС.

Ответом считается любое из двух: нажатие кнопки в боте или отметка о
подтверждении в МИС — в том числе поставленная администратором, когда пациент
позвонил в клинику сам. Такому человеку лид не заводится.

Лида не будет также, если визит отменён или перенесён, приём уже состоялся, до
приёма осталось меньше настроенного порога (звонок человеку у кабинета
бессмысленен), пациент отказался от оповещений или идут тихие часы филиала —
тогда заявка ждёт утра.

---

## Часть 1. Что портал кладёт в CRM

Используется LPTracker Direct API (`https://direct.lptracker.ru`), как он описан
на docs.direct.lptracker.ru. На одну заявку приходится до трёх запросов.

### 1.1. Вход

```
POST /login
{ "login": "...", "password": "...", "service": "Alfa-Wiki", "version": "1.0" }
```

Токен из `result.token` портал держит 12 часов и переиспользует. При ответе 401
входит заново — один раз, без цикла.

Все обращения портала идут через общую очередь не чаще 3 запросов в секунду: это
предел, заявленный в документации.

### 1.2. Контакт

```
GET  /contact/search?project_id=<project>&phone=79001234567
POST /contact
{ "project_id": <project>, "name": "<ФИО>", "details": [{ "type": "phone", "data": "79001234567" }] }
```

Поиск обязателен: пациент ходит в клинику годами, и без него каждый визит заводил
бы новый контакт с тем же номером и своей историей звонков. Телефон всегда в виде
`79XXXXXXXXX`.

### 1.3. Лид

```
POST /lead
{
  "contact_id": <contact>,
  "name": "Напоминание о визите · Иванов Иван Иванович · 22.09.2026 10:00 · Альфа Линия",
  "funnel": 2416247,
  "custom": { "<id поля>": "<значение>", ... }
}
```

`funnel` — шаг «Обзвон роботом», с которого запускается автоворонка обзвона. Номер
шага и номер проекта лежат в настройке портала и меняются в его интерфейсе.

### 1.4. Состав кастомных полей

Портал **не хранит числовые id полей**. Перед отправкой он спрашивает
`GET /project/<project>/customs` и сопоставляет поля **по имени** (регистр и
пробелы по краям не важны). Поле, которого в проекте нет, пропускается, а его имя
пишется в журнал портала.

Четыре поля обязательны по смыслу — без них роботу нечего сказать:

| Имя поля | Что в нём | Пример |
|---|---|---|
| `appointment_id` | номер визита в МИС, **ключ обмена** | `4412308` |
| `patient_name` | ФИО пациента | `Иванов Иван Иванович` |
| `time_start` | дата и время приёма | `2026-09-22 10:00:00` |
| `clinic_title` | клиника визита | `Альфа Линия` |

Остальные портал заполняет, если такие поля в проекте есть:

| Имя поля | Что в нём |
|---|---|
| `time_end` | время окончания приёма |
| `clinic_id` | номер клиники в МИС |
| `doctor_name` | ФИО врача |
| `doctor_id` | номер врача в МИС |
| `patient_id` | номер карты пациента в МИС |
| `mobile` | телефон в виде `79XXXXXXXXX` |
| `room` | кабинет |
| `servises` | специальность приёма |

Время в `time_start` и `time_end` — местное, в том же виде, в котором его отдаёт
МИС (`ГГГГ-ММ-ДД ЧЧ:ММ:СС`). ISO с часовым поясом портал не отправляет намеренно:
в UTC приём смещается на три часа, и робот назвал бы пациенту чужой час.
Человекочитаемое время лежит в названии лида.

**Если удобнее другие имена полей или другой формат времени — скажите, это правка
одной таблицы соответствия на нашей стороне.**

## Часть 2. Что портал ждёт назад

Один метод: итог разговора. Без него звонок ничего не меняет — визит остаётся в
МИС активным, администратор держит под него время, и о неявке узнают в день
приёма.

### 2.1. Адрес и ключ

```
POST https://wiki.medcentralfa.ru/api/public/v1/ai-call/result
Content-Type: application/json
X-Api-Key: <ключ>
```

Ключ выдаёт администратор портала (Администрирование → Интеграции, право
`ai-call:result`). Ключ можно ограничить списком IP — пришлите адреса, с которых
будете обращаться. Каждое обращение пишется в журнал портала.

### 2.2. Тело запроса

```json
{
  "appointment_id": 4412308,
  "result": "confirmed",
  "patient_name": "Иванов Иван Иванович",
  "visit_at": "2026-09-22 10:00:00",
  "clinic": "Альфа Линия",
  "lead_id": 10035871,
  "comment": "Сказал, что придёт"
}
```

Обязательных полей два:

- **`appointment_id`** — номер визита в МИС, тот самый, который приехал в лиде.
  Принимается также под именами `appointmentId`, `visit_id`, `visitId`.
- **`result`** — чем кончился разговор. Принимается также под именами `status`,
  `funnel_step`, `funnelStep`.

Остальные поля необязательны. Портал их сохраняет, но действует по
`appointment_id`: ФИО, время визита и клиника нужны, чтобы в спорном случае было
видно, о каком визите шла речь. `comment` дописывается в карточку визита в МИС при
отмене — администратор должен видеть, чьих рук отмена и что человек сказал.

### 2.3. Значения `result`

Портал понимает свои коды и названия ваших шагов воронки — что удобнее.

| Код | Синонимы, которые принимаются | Что происходит в МИС |
|---|---|---|
| `confirmed` | `подтвердил`, `подтверждён`, `confirm` | **подтверждение визита** |
| `cancelled` | `отменил`, `отмена`, `отказ`, `AI · Отказ`, `refused` | **отмена визита** |
| `no_answer` | `не дозвонились`, `AI · Не дозвонились`, `нет ответа` | только запись в журнал |
| `voicemail` | `автоответчик`, `AI · Автоответчик` | только запись в журнал |
| `hangup` | `бросил трубку`, `сбросил` | только запись в журнал |
| `callback` | `перезвонить`, `AI · Перезвонить`, `позвонить позже` | только запись в журнал |
| `operator` | `перевод на КЦ`, `нужна проверка` | только запись в журнал |
| `unclear` | `разговор без результата`, `AI · Разговор без результата` | только запись в журнал |

Незнакомое значение не отвергается: портал запишет его как `other` и сохранит
присланное тело целиком. Терять итог хуже, чем не понять его — по нему хотя бы
видно, что звонок состоялся.

Актуальный список всегда можно получить у самого сервиса; он же отвечает, какой
исход что меняет:

```
GET https://wiki.medcentralfa.ru/api/public/v1/ai-call/results
X-Api-Key: <ключ>
```

### 2.4. Ответ

```json
{
  "ok": true,
  "requestId": "3f2b…",
  "result": "confirmed",
  "mis": "confirmed",
  "repeated": false
}
```

- `result` — как портал понял присланный исход;
- `mis` — что получилось сделать в МИС: `confirmed`, `cancelled`, `none` (исход
  визита не меняет либо менять было нечего) или `failed` (МИС отказала, причина в
  `misError`);
- `repeated: true` — этот же итог уже был принят раньше, повторно ничего не
  делалось.

Отправлять один и тот же итог дважды безопасно. Портал не подтверждает визит
второй раз и не отменяет уже отменённое.

Перед отменой портал спрашивает МИС о текущем состоянии визита. Если приём уже
состоялся или визит отменён, отмена не производится, и в ответе будет
`"mis": "none"` с пояснением: звонок мог состояться после приёма, а отменить
состоявшийся визит задним числом — испортить статистику и деньги.

### 2.5. Ошибки

| Код | Когда |
|---|---|
| 400 | нет `appointment_id` или `result` |
| 401 / 403 | ключ не тот, отозван, нет права `ai-call:result` или обращение не с разрешённого IP |
| 404 | визита с таким номером портал не знает |
| 429 | слишком часто — повторите позже |
| 500 | наша беда; повторите через несколько минут |

Тело ошибки:

```json
{ "ok": false, "error": "not_found", "message": "Визит не найден" }
```

## Что нужно от вас для запуска

1. **Запустить автоворонку обзвона.** На момент подключения все автоворонки
   проекта числятся остановленными (`status: 0`), в том числе «Подтверждение
   записи». Пока ни одна не запущена, лиды будут копиться без звонков.
2. **Подтвердить шаг воронки.** Портал кладёт лид на «Обзвон роботом»
   (id 2416247). Если автоворонка ждёт другого шага — назовите его.
3. **IP-адреса**, с которых будете присылать итоги звонков, чтобы ограничить ключ.
4. **Подтвердить состав полей** из раздела 1.4 и формат времени.

Со стороны портала настройка живёт в Администрирование → Открытая линия →
Рассылка: «CRM для ИИ-звонков» (логин, пароль, проект, шаг воронки; кнопка
«Проверить» показывает, какие из полей нашлись в проекте) и включатель «передавать
заявки» в карточке каждого филиала. Сроки ожидания задаются у события
«Напоминание о визите» на вкладке «Тексты».
