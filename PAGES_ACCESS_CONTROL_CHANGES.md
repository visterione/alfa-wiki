# Изменения в системе контроля доступа к страницам и папкам

## Обзор изменений

Реализованы следующие улучшения системы контроля доступа к страницам и папкам:

1. **Общедоступный режим чтения страниц** - все авторизованные пользователи могут просматривать страницы без ограничений по ролям
2. **Настройка доступа для папок по ролям** - папки теперь поддерживают `allowedRoles` аналогично страницам
3. **Фильтрация папок в проводнике** - пользователи видят только папки, к которым у них есть доступ
4. **Фильтрация в сайдбаре** - элементы сайдбара фильтруются по доступу пользователя

---

## 1. Общедоступный режим чтения страниц

### Логика доступа

- **Просмотр страниц** (`/page/:slug`) - доступен всем авторизованным пользователям
- **Страницы с пустым `allowedRoles`** - доступны всем для чтения
- **Страницы с заполненным `allowedRoles`** - доступны только пользователям с соответствующими ролями
- **Редактирование/создание/удаление** - требует `adminAccess.pages = true` или соответствующих прав

### Защита маршрутов

- `/page/:slug` - доступен всем авторизованным пользователям ✓
- `/page/:slug/edit` - требует `pages.write` permission
- `/new-page` - требует `pages.write` permission
- `/admin/pages` - требует `adminAccess.pages = true`

### Файлы изменений

- **Backend**: `c:\alfa-wiki\backend\routes\pages.js` (строки 125-131)
  - Проверка `allowedRoles` только для страниц с непустым массивом ролей
- **Frontend**: `c:\alfa-wiki\frontend\src\App.js` (строки 67-68)
  - Маршруты просмотра доступны всем авторизованным пользователям

## 3. Фильтрация папок в проводнике

### Логика фильтрации

**Файл**: `c:\alfa-wiki\backend\routes\folders.js` (строки 8-116)

#### Функции проверки доступа:

1. **`canAccessFolder(folder, userRoleIds, isAdmin)`**
   - Админы видят всё
   - Папки с пустым `allowedRoles` доступны всем
   - Папки с заполненным `allowedRoles` - только пользователям с соответствующими ролями

2. **`canAccessPage(page, userRoleIds, isAdmin)`**
   - Админы видят всё
   - Страницы с пустым `allowedRoles` доступны всем
   - Страницы с заполненным `allowedRoles` - только пользователям с соответствующими ролями

3. **`hasAccessToFolderContent(folderId, userRoleIds, isAdmin)`**
   - Рекурсивная проверка доступа к содержимому папки
   - Проверяет доступные страницы в папке
   - Проверяет доступные подпапки рекурсивно

### Алгоритм фильтрации в `/browse`

1. Получить все папки в текущей директории
2. Для каждой папки:
   - Если есть прямой доступ к папке → проверить содержимое → показать папку
   - Если нет прямого доступа → проверить доступ к содержимому → показать папку, если есть доступ к содержимому
3. Фильтровать страницы по `allowedRoles`

### Поведение

- **Папки с доступом, но без содержимого** - показываются
- **Папки без доступа, но с доступным содержимым** - показываются
- **Папки без доступа и без доступного содержимого** - скрываются

## 4. Фильтрация в сайдбаре

### Логика фильтрации

**Файл**: `c:\alfa-wiki\backend\routes\sidebar.js` (строки 39-95)

#### Проверки доступа:

1. **Элемент сайдбара** (`item.allowedRoles`)
   - Проверка ролей самого элемента сайдбара

2. **Ссылка на страницу** (`item.page.allowedRoles`)
   - Проверка черновика (`isPublished`)
   - Проверка ролей страницы

3. **Ссылка на папку** (`item.folder.allowedRoles`)
   - Проверка ролей папки
   - Фильтрация страниц внутри папки по их `allowedRoles`

### Изменения в запросе

- Добавлено поле `allowedRoles` в атрибуты Page и Folder
- Фильтрация страниц внутри папок сайдбара (`folderPages`)

## Примеры использования

### Создание папки с ограничениями по ролям

1. Перейти в `/admin/pages`
2. Нажать "Новая папка"
3. Заполнить название и описание
4. В разделе "Доступ по ролям" выбрать нужные роли
5. Сохранить

### Создание общедоступной страницы

1. Создать страницу через `/admin/pages` или `/new-page`
2. В настройках страницы оставить поле `allowedRoles` пустым
3. Опубликовать страницу
4. Страница будет доступна всем авторизованным пользователям

### Создание страницы для определённых ролей

1. Создать страницу через `/admin/pages` или `/new-page`
2. В редакторе страницы → настройки (Settings)
3. Выбрать роли в разделе "Allowed Roles"
4. Опубликовать страницу
5. Страница будет видна только пользователям с выбранными ролями

## Тестирование

### Сценарии тестирования:

1. **Общедоступные страницы**
   - Создать страницу без ограничений по ролям
   - Войти под пользователем без прав на страницы
   - Убедиться, что страница доступна для чтения

2. **Папки с ограничениями**
   - Создать папку с ограничением по роли "Admin"
   - Войти под пользователем без роли "Admin"
   - Убедиться, что папка не видна в проводнике

3. **Папки с доступным содержимым**
   - Создать папку с ограничением по роли "Admin"
   - Создать в ней страницу без ограничений
   - Войти под пользователем без роли "Admin"
   - Убедиться, что папка видна (так как есть доступ к содержимому)

4. **Сайдбар**
   - Добавить папку в сайдбар
   - Создать в папке страницы с разными `allowedRoles`
   - Войти под разными пользователями
   - Убедиться, что видны только доступные страницы

## Обратная совместимость

- Существующие папки получат пустой `allowedRoles` (доступны всем)
- Существующие страницы продолжат работать как прежде
- Маршруты и API остались обратно совместимыми

## Технические детали

### Производительность

- Фильтрация папок в проводнике использует рекурсивные запросы
- При большом количестве папок (>100) может наблюдаться задержка
- Рекомендуется кешировать результаты фильтрации на уровне приложения

### Безопасность

- Все проверки доступа выполняются на backend
- Frontend UI отражает backend permissions
- Админы (`isAdmin: true`) обходят все проверки доступа
