# Руководство по миграции: Медцентры и множественные роли

## Обзор изменений

Данная миграция добавляет следующие возможности:

1. **Медицинские центры** - каждый пользователь теперь может быть привязан к одному или нескольким медцентрам
2. **Множественные роли** - пользователь может иметь несколько ролей одновременно

## Изменения в базе данных

### Новые таблицы:

1. **med_centers** - справочник медицинских центров (6 записей)
   - Альфа
   - Кидс
   - Проф
   - Линия
   - Смайл
   - 3К

2. **user_med_centers** - связующая таблица (many-to-many)
   - userId
   - medCenterId

3. **user_roles** - связующая таблица для множественных ролей (many-to-many)
   - userId
   - roleId

### Изменения в моделях:

- `User` получил новые связи:
  - `user.medCenters` - массив медцентров
  - `user.roles` - массив ролей (новая система)
  - `user.role` - одна роль (старая система, оставлена для совместимости)

## Шаги по миграции

### 1. Создание резервной копии

**ВАЖНО:** Перед миграцией обязательно создайте резервную копию базы данных!

```bash

```

## Использование новых возможностей

### Backend (routes/users.js)

При создании/обновлении пользователя теперь принимаются новые поля:

```javascript
{
  username: "ivanov",
  displayName: "Иванов Иван",
  email: "ivanov@example.com",
  roleIds: ["role-uuid-1", "role-uuid-2"], // Массив ID ролей
  medCenterIds: ["medcenter-uuid-1", "medcenter-uuid-2"], // Массив ID медцентров
  isAdmin: false,
  isActive: true
}
```

### Frontend (AdminUsers.js)

Новый интерфейс позволяет:
- Выбирать несколько ролей через чекбоксы
- Выбирать несколько медцентров через чекбоксы
- Просматривать все роли и медцентры пользователя в таблице

### Проверка прав доступа (AuthContext)

Функции `hasPermission()` и `canAccessPage()` теперь проверяют права во всех ролях пользователя:

```javascript
// Пользователь получит доступ, если хотя бы одна из его ролей имеет нужное право
const canEdit = hasPermission('pages', 'write');

// Пользователь получит доступ к странице, если хотя бы одна из его ролей в allowedRoles
const canView = canAccessPage(page);
```


### Получить пользователя с ролями и медцентрами
```
GET /api/users/:id

Response:
{
  id: "...",
  username: "ivanov",
  displayName: "Иванов Иван",
  email: "ivanov@example.com",
  role: { ... },              // Старая система (для совместимости)
  roles: [{ ... }, { ... }],  // Новая система
  medCenters: [{ ... }],
  isAdmin: false,
  isActive: true
}
```

## Обратная совместимость

Старая система с одной ролью (`user.roleId`, `user.role`) **сохранена** для обратной совместимости.

Рекомендуется постепенно переходить на новую систему множественных ролей:
1. Используйте `user.roles` вместо `user.role`
2. Отправляйте `roleIds` вместо `roleId`
3. После полного перехода можно удалить поле `roleId` из таблицы users
