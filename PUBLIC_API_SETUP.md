# Запуск приёма заявок с сайта — инструкция

Что делает функционал: сайт клиники отправляет заполненную пациентом форму к нам
в вики, заявка сохраняется в базу и бот пишет её в групповой чат.

Документ для нас (настройка на сервере). Инструкции для программиста сайта — отдельные
файлы: `PUBLIC_API_PATIENT_FORM.md` (регистрация пациента) и
`PUBLIC_API_TAX_DEDUCTION_FORM.md` (справка для налогового вычета).

Формы независимы: у каждой свой адрес, свой набор полей, свой шаблон сообщения и своя
настройка чата. Бот у них общий.

---

## 1. Накатить миграцию

```bash
cd <ПУТЬ_К_ПРОЕКТУ>/alfa-wiki/backend
node scripts/migratePublicApi.js
```

Подключение берётся из `backend/.env` — пароль вводить не нужно. Скрипт печатает
состояние до и после и сам проверяет, что всё создалось. Повторный запуск безопасен:
если уже применена, скрипт ничего не делает.

Посмотреть состояние, ничего не меняя:

```bash
node scripts/migratePublicApi.js --check
```

Создаются три таблицы: `api_clients` (ключи внешних систем), `submissions` (заявки),
`api_request_logs` (аудит обращений). Тот же SQL лежит в
`migrations/ver. 6.06 add-public-api.sql`, если удобнее накатить через `psql`.

---

## 2. Создать бота и отметить ему формы

В вики: **Админка → Боты → Создать**.

- Имя: `Заявки на справки`
- Username: `tax_forms_bot`
- **Заявки с сайта, которые доставляет бот** — отметить нужные

Лучше заводить отдельного бота под каждое назначение («Заявки на справки», «Записи
с сайта»), а не одного на всё: тогда набор чатов у каждого свой и ничего не смешивается.

---

## 3. Создать групповой чат и добавить в него бота

1. В мессенджере вики создать группу, например «Справки».
2. Добавить туда сотрудников, которые будут разбирать заявки. Состав участников
   держать узким: в сообщениях будут паспортные данные пациентов.
3. Добавить бота из шага 2: в чате → «Добавить участника» → раздел **«Боты»**
   внизу списка.

**Это и есть настройка доставки.** Бот при входе сам напишет в чат, что теперь
сюда приходит. Никаких id чата выписывать и никуда вносить не нужно.

Проверить и поправить можно прямо в чате:

```
/subscriptions              что этот чат получает
/subscribe <тип формы>      подписать на форму
/unsubscribe <тип формы>    отписать
/forms                      список всех форм
```

Подписки меняет только администратор чата. Общий список «кто на что подписан» —
**Админка → Интеграции → Куда уходят заявки**.

---

## 4. Перезапустить бэкенд

```bash
pm2 restart alfa-wiki
```

В логе должна появиться строка `⏰ submissionsRetryCron: зарегистрирован (ежеминутно)`.

Переменные `PUBLIC_FORMS_BOT_TOKEN` и `PUBLIC_FORM_*_CHAT_ID` в `.env` больше не нужны —
с ver. 6.15 маршрут задаётся членством бота в чате. Пока переменные не удалены, они
работают как запасной вариант для форм, у которых нет ни одной подписки.

---

## 4.1. Проверить лимит размера тела в nginx

Нужно только для форм с файлами (справка для налогового вычета).

```bash
sudo nginx -T | grep client_max_body_size
```

По умолчанию в nginx стоит **1 МБ** — файл на 2 МБ до бэкенда не дойдёт, сайт получит
413 от nginx, а не наш ответ. В вики загружаются видео, поэтому лимит, скорее всего,
уже поднят. Если команда ничего не вывела — добавить в конфиг:

```nginx
client_max_body_size 25m;
```

и `sudo nginx -s reload`.

## 5. Выдать ключ сайту

**Админка → Интеграции → Выдать ключ.**

- Название системы: `Сайт medcentralfa.ru`
- Откуда вызывают: с сервера сайта (обычный случай) или из браузера
- Отметить галочками разрешённые формы

Ключ вида `wk_live_...` показывается **один раз** — в базе хранится только его хеш.
Передать программисту сайта защищённым каналом (не в чате и не письмом открытым
текстом).

Если форма отправляется прямо из браузера, а не с сервера сайта, выберите тип «из
браузера» и обязательно заполните список Origin: такой ключ виден любому посетителю
страницы, и без белого списка адресов им сможет пользоваться кто угодно.

### Добавить форму существующему ключу

**Интеграции → нужная строка → «Изменить» → поставить галочку.**

Ключ при этом не меняется — разработчику сайта ничего передавать не нужно, он просто
начинает слать на новый адрес тем же ключом. Перевыпуск ключа нужен только при утечке.

Консольный `scripts/createApiClient.js` остаётся рабочим, но менять права умеет
только интерфейс.

Отозвать ключ:

```sql
UPDATE api_clients SET "isActive" = false WHERE name = 'Сайт medcentralfa.ru';
```

## 6. Проверить

Доступность контура (ключ не нужен):

```bash
curl https://wiki.medcentralfa.ru/api/public/v1/ping
```

Тестовая заявка — подставить свой ключ:

```bash
curl -X POST https://wiki.medcentralfa.ru/api/public/v1/forms/patient-registration \
  -H "X-Api-Key: wk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "lastName":"Тестов","firstName":"Тест","birthDate":"1985-03-12",
    "documentSeries":"4510","documentNumber":"123456",
    "documentIssuedBy":"ОУФМС России","documentIssuedAt":"2010-05-20",
    "documentDepartmentCode":"770-001",
    "district":"ЮЗАО","city":"Москва","street":"Профсоюзная",
    "phone":"+79991234567","email":"test@example.com",
    "personalDataConsent":true
  }'
```

Ожидаемый ответ: `{"ok":true,"id":"...","duplicate":false,"delivered":true}`
и сообщение в групповом чате.

Если `"delivered": false` — заявка принята и записана, но в чат не ушла. Смотреть
в **Интеграции → Заявки**: там по каждой заявке видно, в какие чаты она ушла, где
не прошла и почему, и есть кнопка «Переотправить».

То же самое запросом:

```sql
SELECT s."createdAt", s."formType", d.status, d.attempts, d.error, c.name AS чат
FROM submissions s
LEFT JOIN submission_deliveries d ON d."submissionId" = s.id
LEFT JOIN chats c ON c.id = d."chatId"
ORDER BY s."createdAt" DESC LIMIT 10;
```

Частые причины: бот не добавлен ни в один чат, боту не отмечена эта форма в админке,
бота убрали из чата. После исправления перепосылать вручную не нужно — крон добьёт
доставку в течение минуты.

## Что где лежит

| Что | Где |
|---|---|
| Приём заявок | `backend/routes/public/v1/forms.js` |
| Описание форм и шаблоны сообщений | `backend/services/public/forms/` |
| Приём и проверка файлов | `backend/services/public/fileIntake.js` |
| Загруженные файлы | `backend/uploads/public-submissions/ГГГГ-ММ/` |
| Сохранение и доставка | `backend/services/public/submissionService.js` |
| Проверка ключей, лимиты, аудит | `backend/middleware/publicApi.js` |
| Повторная доставка | `backend/cron/submissionsRetryCron.js` |
| Маршруты доставки, команды в чате | `backend/services/public/subscriptionService.js` |
| Управление ключами | `backend/routes/api-clients.js` + Админка → Интеграции |
| Переезд с `.env` на подписки | `backend/scripts/migrateFormRouting.js` |

## Полезные запросы

Заявки за сегодня:

```sql
SELECT "createdAt", payload->>'lastName' AS "фамилия", payload->>'phone' AS "телефон",
       "deliveryStatus"
FROM submissions
WHERE "createdAt" >= current_date
ORDER BY "createdAt" DESC;
```

Обращения к API за последний час (в т.ч. отклонённые):

```sql
SELECT "createdAt", path, "statusCode", "errorCode", ip
FROM api_request_logs
WHERE "createdAt" > now() - interval '1 hour'
ORDER BY id DESC;
```

## Добавить новую форму

Ни таблицы, ни миграции, ни `.env`, ни перезапуска:

1. **Код.** Скопировать `backend/services/public/forms/patientRegistration.js`,
   описать поля и шаблон сообщения; добавить модуль в массив `FORMS` в
   `backend/services/public/formRegistry.js`.
2. **Админка → Боты** → нужному боту отметить новую форму. Если бот уже сидит в
   чатах, подписки там появятся сразу.
3. **Админка → Интеграции** → нужному ключу поставить галочку новой формы.

Разработчику сайта сообщается только адрес нового эндпоинта — ключ у него прежний.
