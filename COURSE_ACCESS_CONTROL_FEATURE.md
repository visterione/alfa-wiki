# Система контроля доступа к курсам по ролям и медцентрам

## Описание

Добавлена система гранулярного контроля доступа к курсам с использованием правила **"И"** (пересечение).

### Логика доступа

Пользователь получает доступ к курсу только если выполняются **ОБА** условия:
1. **Роль пользователя** входит в список разрешенных ролей (или ограничения по ролям не установлены)
2. **Медцентр пользователя** входит в список разрешенных медцентров (или ограничения по медцентрам не установлены)

**Важно:** Если для курса не заданы ограничения (пустые списки ролей И медцентров), курс доступен **всем** пользователям.

## Изменения в базе данных

### Новые таблицы

#### `course_roles`
Связь курсов с ролями (Many-to-Many)

```sql
- id: UUID (PK)
- courseId: UUID (FK -> courses.id, ON DELETE CASCADE)
- roleId: UUID (FK -> roles.id, ON DELETE CASCADE)
- createdAt: TIMESTAMP
- updatedAt: TIMESTAMP
- UNIQUE(courseId, roleId)
```

**Индексы:**
- `idx_course_roles_course` на `courseId`
- `idx_course_roles_role` на `roleId`

#### `course_medcenters`
Связь курсов с медцентрами (Many-to-Many)

```sql
- id: UUID (PK)
- courseId: UUID (FK -> courses.id, ON DELETE CASCADE)
- medCenterId: UUID (FK -> med_centers.id, ON DELETE CASCADE)
- createdAt: TIMESTAMP
- updatedAt: TIMESTAMP
- UNIQUE(courseId, medCenterId)
```

**Индексы:**
- `idx_course_medcenters_course` на `courseId`
- `idx_course_medcenters_medcenter` на `medCenterId`

## Изменения в backend

### 1. Модели (backend/models/index.js)

Добавлены новые модели:
- **CourseRole** - модель связи курсов и ролей
- **CourseMedCenter** - модель связи курсов и медцентров

Обновлена модель **Course** с новыми связями:
```javascript
// Course & Role (Many-to-Many)
Course.belongsToMany(Role, {
  through: CourseRole,
  foreignKey: 'courseId',
  as: 'allowedRoles'
});

// Course & MedCenter (Many-to-Many)
Course.belongsToMany(MedCenter, {
  through: CourseMedCenter,
  foreignKey: 'courseId',
  as: 'allowedMedCenters'
});
```

### 2. Middleware (backend/middleware/auth.js)

Добавлена функция **checkCourseAccess**:
- Проверяет доступ пользователя к конкретному курсу
- Реализует логику пересечения (AND) для ролей и медцентров
- Администраторы имеют доступ ко всем курсам
- Неопубликованные курсы доступны только администраторам

### 3. API Routes (backend/routes/courses.js)

#### Обновленные endpoints:

**POST /api/courses/admin**
- Создание курса с указанием разрешенных ролей и медцентров
- Новые параметры: `allowedRoleIds`, `allowedMedCenterIds` (массивы UUID)

**PUT /api/courses/admin/:id**
- Обновление курса с изменением ограничений доступа
- Поддержка пустых массивов для снятия ограничений

**GET /api/courses/admin/:id/edit**
- Возвращает курс с загруженными связями `allowedRoles` и `allowedMedCenters`

**GET /api/courses/admin/all**
- Список всех курсов (для админки) с информацией о доступе

**GET /api/courses**
- Список опубликованных курсов с фильтрацией по доступу текущего пользователя
- Применяется логика AND для фильтрации
- Для обычных пользователей данные о доступе скрыты

## Изменения в frontend

### 1. AdminCourseEditor (frontend/src/pages/admin/AdminCourseEditor.js)

Добавлена секция **"Контроль доступа"** во вкладке "Основная информация":

**Новые поля формы:**
- `allowedRoleIds` - массив ID разрешенных ролей
- `allowedMedCenterIds` - массив ID разрешенных медцентров

**Новый UI:**

- Чекбоксы для выбора доступных медцентров

- При монтировании компонента загружаются все доступные роли и медцентры

## Примеры использования

### Пример 1: Курс только для врачей в Альфе

**Настройки:**
- Роли: "Врач"
- Медцентры: "Альфа"

**Доступ получат:** Только пользователи с ролью "Врач" **И** медцентром "Альфа"

### Пример 2: Курс для всех врачей (независимо от медцентра)

**Настройки:**
- Роли: "Врач"
- Медцентры: (не выбраны)

**Доступ получат:** Все пользователи с ролью "Врач" из любого медцентра

### Пример 3: Курс для всех в медцентре "Кидс"

**Настройки:**
- Роли: (не выбраны)
- Медцентры: "Кидс"

**Доступ получат:** Все пользователи медцентра "Кидс" с любой ролью

### Пример 4: Публичный курс

**Настройки:**
- Роли: (не выбраны)
- Медцентры: (не выбраны)

**Доступ получат:** Все пользователи системы

## Тестирование

### Проверочный список:

1. **Создание курса:**
   - [ ] Создать курс без ограничений - доступен всем
   - [ ] Создать курс с ограничением по ролям - доступен только выбранным ролям
   - [ ] Создать курс с ограничением по медцентрам - доступен только выбранным медцентрам
   - [ ] Создать курс с ограничениями по ролям И медцентрам - доступен только при совпадении обоих

2. **Редактирование курса:**
   - [ ] Добавить ограничения к существующему курсу
   - [ ] Удалить ограничения (очистить чекбоксы)
   - [ ] Изменить набор разрешенных ролей/медцентров

3. **Проверка доступа:**
   - [ ] Админ видит все курсы в списке
   - [ ] Обычный пользователь видит только доступные курсы
   - [ ] Пользователь с подходящей ролью, но не тем медцентром - не видит курс
   - [ ] Пользователь с подходящим медцентром, но не той ролью - не видит курс
   - [ ] Пользователь с подходящими ролью И медцентром - видит курс

4. **Edge cases:**
   - [ ] Неопубликованный курс не доступен обычным пользователям
   - [ ] Админ видит неопубликованные курсы
   - [ ] При удалении роли/медцентра связи каскадно удаляются
