# Аудит Warehouse относительно ТЗ

Дата проверки: 11.08.2026.

## Рамки оценки

Оценка выполнена по текущему коду, миграциям, API и пользовательским экранам. Успешная сборка или наличие таблицы не означает, что функция полностью готова для пользователя: для статуса «готово» проверялся сквозной сценарий через интерфейс.

Интеграция с 1С в дефицит не включается. Это сознательно отложенная функция: сейчас источником данных является сама вики. XML для 1С, сверка с 1С и двусторонний REST-обмен не требуются на текущем этапе. При этом технические заделы (`oneCRef`, `oneCStatus`, `warehouse_outbox`) сохранены.

Обозначения:

- **Готово** — есть схема, backend и пригодный пользовательский интерфейс.
- **Частично** — реализована только часть сценария, либо есть backend без полного интерфейса/автоматизации.
- **Нет** — рабочей реализации не найдено.

## Резюме

Warehouse уже является крупным работающим модулем, а не прототипом: присутствуют 29 складских таблиц, иерархия помещений, карточки ОС, материалы и партии, QR/этикетки, публичные карточки, отчёты, тепловая карта, дашборд кабинета и ролевая модель.

Ориентировочная зрелость:

- технический фундамент и backend: **около 75–80 %**;
- готовность ежедневного пользовательского процесса: **около 50–60 %**;
- готовность исходного ТЗ целиком без 1С: **около 60–65 %**.

Главный разрыв — не в структуре данных, а в операционной работе. API для выдачи, перемещения, ТО, ремонтов, инвентаризаций и котировок существует, но большинство этих действий нельзя полноценно оформить из интерфейса Warehouse.

## Тепловая карта загрузки

Статус: **частично готово**.

Готово:

- интерактивный SVG-план этажа с масштабированием и перемещением;
- редактор прямоугольных и полигональных помещений, контур этажа и подложка;
- зелёная/жёлтая/красная индикация загрузки;
- переключатели: загрузка, стоимость/число активов, дефицит, просрочка, просроченное ТО, ремонт и простой;
- расчёт загрузки по фактическим интервалам расписания МИС с устранением пересечений;
- отдельный список простаивающего оборудования.

Не завершено:

- ежедневный автоматический пересчёт не зарегистрирован как cron-задача; доступен ручной endpoint;
- исходная формула «журнал выдачи + расписание» изменена: загрузка кабинета считается по расписанию МИС, а простой активов — по отсутствию учётных операций;
- нет автоматических рекомендаций по перераспределению и расчёта предотвращённой закупки;
- без алиасов кабинетов МИС и реального расписания основной показатель не рассчитывается.

## Цифровой паспорт актива

Статус: **частично готово**.

Готово:

- публичный read-only URL без авторизации;
- основные данные, серийный номер, статус, локация, гарантия и следующее ТО;
- история ТО, ремонтов и движений;
- публично разрешённые документы и фото;
- защита длинным случайным токеном и ограничением частоты запросов.

Расхождения с ТЗ:

- в публичной ленте движения показаны только тип и дата, без маршрута, причины и ответственного;
- текущий ответственный намеренно обезличен: выводятся роль и отделение, но не ФИО;
- дата закупки на публичной карточке не выводится;
- стоимость и внутренние документы скрыты по соображениям безопасности. Это разумное ограничение, но формально публичная страница не содержит «всю историю жизни» из ТЗ.

Внутренняя авторизованная карточка значительно ближе к полному digital twin: там есть МОЛ, стоимость, амортизация, файлы, ТО, ремонты и детальная лента.

## Приоритетный план завершения

### P0 — довести до рабочего складского контура

1. Сделать единый экран складского документа: приём, выдача, перемещение, возврат, списание, в ремонт/из ремонта; выбор партии, количества, локаций, МОЛ, врача и причины; подписание документа.
2. Сделать UI создания/закрытия ТО и ремонта из карточки актива.
3. Сделать UI инвентаризации: создать сессию, сканировать QR, вводить факт, закрывать и оформлять расхождения.
4. Решить правило обязательной локации: запретить создание ОС без кабинета/места хранения либо ввести явную транзитную локацию «Неразмещённые».
5. Добавить интеграционные тесты складских проводок: приход → перемещение → выдача → возврат/списание, запрет отрицательного остатка и просроченной партии.

### P1 — отчётность внутреннего контура

1. Доработать амортизацию для внутреннего режима без 1С: ручной ежемесячный снимок/начисление либо явно переименовать отчёт в «Состояние амортизации на дату».
2. Расширить фильтры отчётов и переходы к первичным документам.

### P2 — аналитика и удобство

1. ABC/XYZ-анализ.
2. Полноценная PWA-обвязка сканера и fallback-декодер QR для Safari/Firefox.
3. Сохранённые варианты и регламентная рассылка отчётов.
4. UI сравнительной таблицы котировок.
5. Рекомендации по перераспределению только после появления надёжных данных об использовании конкретного оборудования.

## Итоговое заключение

Модуль уже подходит для ведения справочников, карточек оборудования, визуального контроля помещений, QR-маркировки, просмотра остатков и формирования основных отчётов внутри вики. Пока его нельзя считать полностью готовым складским контуром: критические операции в основном существуют на уровне API, а не на уровне ежедневной работы сотрудников.

Отказ от 1С на текущем этапе не мешает запуску. Для внутреннего запуска важнее сначала закрыть P0 и автоматические уведомления P1; заделы 1С можно оставить выключенными без удаления из схемы.
