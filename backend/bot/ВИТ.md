### 1.0. Общие правила для всех отчётов

**Единая шапка.** Каждый отчёт в PDF и XLSX начинается блоком:

```
ООО «Медицинский центр»                                    Отчёт сформирован:
                                                           10.08.2026 14:32 (МСК)
        ОБОРОТНО-САЛЬДОВАЯ ВЕДОМОСТЬ ПО ЛОКАЦИЯМ           Пользователь: Петрова А. В.
        за период 01.07.2026 — 31.07.2026                  Система: МедАктив v1.4.2

Отбор: Корпус = Главный; Отделение = Хирургия; Тип = Материалы
```

**Единые элементы управления в веб-интерфейсе:**

| Элемент | Поведение |
|---|---|
| Период | Пресеты: сегодня, неделя, месяц, квартал, год, произвольный |
| Дерево локаций | Множественный выбор с наследованием: выбор отделения включает все его кабинеты |
| Группировка | Перетаскиваемые уровни: Корпус → Отделение → Кабинет → Место хранения → Номенклатура |
| Показатели | Чекбоксы: показывать нулевые остатки, показывать в количестве / в сумме / в обоих |
| Сохранённые настройки | Пользователь сохраняет вариант отчёта с именем; варианты можно шарить на роль |
| Drill-down | Клик по любой сумме → список первичных документов, сформировавших её |
| Экспорт | XLSX / PDF / XML (1С) / CSV. Свыше 50 000 строк — асинхронно со ссылкой на почту |
| Регламент | Любой отчёт ставится на расписание с рассылкой получателям |

**Форматирование XLSX (обязательное):** закреплённая шапка (`freeze_panes`), автофильтр по строке заголовков, ширина колонок по содержимому, числовые форматы (`# ##0,00` для сумм, `# ##0,000` для количеств), группировка строк по уровням иерархии (сворачиваемые «плюсики»), итоговая строка жирным с заливкой, условное форматирование для отклонений, отдельный лист «Параметры отбора».

### 1.1. Отчёт № 1. Оборотно-сальдовая ведомость по складам и локациям

**Код:** `RPT-TURNOVER` · **Эндпоинт:** `GET /reports/turnover` · **Роли:** бухгалтер, зав. складом, зав. отделением (в рамках своего отделения), аудитор

**Назначение.** Классическая ОСВ, но с разрезом по физическим локациям, которых нет в 1С. Отвечает на вопрос «что и на какую сумму лежит в каждом кабинете и как это изменилось за период».

**Параметры отбора:** период (обязательно), дерево локаций, тип объекта (ОС / материалы / всё), категория, номенклатурная группа, МОЛ, показывать нулевые остатки (по умолчанию — нет), единица измерения (базовая / упаковки), валюта суммы (только руб.).

**Структура колонок:**

| № | Колонка | Тип | Описание |
|---|---|---|---|
| 1 | Локация / Номенклатура | текст, иерархия | Многоуровневая группировка со сворачиванием |
| 2 | Код | текст | Код номенклатуры или инв. № |
| 3 | Ед. | текст | Единица измерения |
| 4 | **Сальдо на начало — Кол-во** | число (3 зн.) | Остаток на начало периода |
| 5 | **Сальдо на начало — Сумма** | деньги | |
| 6 | **Приход — Кол-во** | число | Поступление, возвраты, оприходование излишков |
| 7 | **Приход — Сумма** | деньги | |
| 8 | **Расход — Кол-во** | число | Выдача, списание, перемещение вовне, недостачи |
| 9 | **Расход — Сумма** | деньги | |
| 10 | **Сальдо на конец — Кол-во** | число | Расчётное: гр.4 + гр.6 − гр.8 |
| 11 | **Сальдо на конец — Сумма** | деньги | |
| 12 | Доля, % | процент | Доля позиции в сумме итога локации |
| 13 | Мин. остаток | число | Из `reorder_rules` |
| 14 | Статус | бейдж | 🔴 ниже минимума · 🟡 близко к минимуму · 🟢 норма |

**Экспорт:** XLSX (иерархия — группировкой строк), PDF (альбомная ориентация, A4), XML для 1С.

### 1.2. Отчёт № 2. Движение активов за период

**Код:** `RPT-MOVEMENT` · **Эндпоинт:** `GET /reports/asset-movement` · **Роли:** зав. отделением, зав. складом, бухгалтер, аудитор

**Назначение.** Полный аудиторский след перемещений оборудования: кто, что, откуда, куда, когда, зачем и на основании какого документа. Основной инструмент при разборе недостач.

**Параметры отбора:** период, тип операции, локация «откуда», локация «куда», конкретный актив, МОЛ, инициатор, причина, только межотделенческие перемещения (чекбокс).

### 1.4. Отчёт № 4. Просроченные и истекающие позиции

**Код:** `RPT-EXPIRING` · **Эндпоинт:** `GET /reports/expiring` · **Роли:** зав. складом, старшая медсестра, зав. отделением, эпидемиолог

### 1.8. Отчёт № 8. Тепловая карта загрузки

**Код:** `RPT-HEATMAP` · **Эндпоинт:** `GET /analytics/heatmap`

**Методика расчёта.** Загрузка кабинета рассчитывается ночным заданием за предыдущие сутки и агрегируется за выбранный период:

```
utilization_pct = (used_hours / available_hours) × 100

used_hours       = Σ по активам кабинета:
                     часы приёма из расписания 1С:Медицина (если актив привязан к кабинету приёма)
                   + часы использования по журналу выдачи (issue → return)
available_hours  = Σ (daily_capacity_hours актива × рабочие дни периода)
                   − часы простоя по ремонту и ТО

Зоны: G < 60 % · Y 60–85 % · R > 85 %
Актив считается простаивающим (idle), если не участвовал ни в одной операции ≥ 14 дней.
```

**Визуализация:** SVG-план этажа, кабинеты залиты цветом зоны. Наведение — всплывающая подсказка. Клик — переход в дашборд кабинета.

## Приложение А. Маска инвентарного номера

**Формат:** `[ПРЕФИКС]-[ГОД]-[КОД_СПЕЦИАЛЬНОСТИ]-[ПОРЯДКОВЫЙ_№]`

```
МЦ  -  2025  -  ХИРУРГ  -  00341
│       │        │           │
│       │        │           └─ Порядковый номер, 5 цифр с ведущими нулями,
│       │        │              счётчик независим для каждой тройки
│       │        │              (префикс, год, специальность)
│       │        └───────────── Код специальности из справочника specialties.code
│       └────────────────────── Год постановки на учёт (4 цифры)
└────────────────────────────── Префикс организации, настраивается (1–8 символов)
```

**Справочник кодов специальностей (базовый набор, расширяемый):**

| Код | Специальность | Код | Специальность |
|---|---|---|---|
| `ХИРУРГ` | Хирургия | `ЛАБОР` | Лаборатория |
| `ТЕРАП` | Терапия | `ФИЗИО` | Физиотерапия |
| `ПЕДИАТ` | Педиатрия | `ГИНЕК` | Гинекология |
| `СТОМАТ` | Стоматология | `ОФТАЛЬМ` | Офтальмология |
| `ЛУЧДИАГ` | Лучевая диагностика | `ЛОР` | Оториноларингология |
| `РЕАНИМ` | Реанимация и ИТ | `КАРДИО` | Кардиология |
| `ЭНДОСК` | Эндоскопия | `АХО` | Административно-хозяйственный |

**Алгоритм генерации (псевдокод):**

```python
def generate_inventory_number(specialty_code: str, year: int, conn) -> str:
    prefix = settings.INVENTORY_PREFIX          # 'МЦ'
    key = f"{prefix}:{year}:{specialty_code}"
    # Блокировка на уровне транзакции — исключает гонку при параллельном создании
    conn.execute("SELECT pg_advisory_xact_lock(hashtext(%s))", (key,))
    seq = conn.execute("""
        INSERT INTO inventory_counters (prefix, year, specialty_code, last_value)
        VALUES (%s, %s, %s, 1)
        ON CONFLICT (prefix, year, specialty_code)
        DO UPDATE SET last_value = inventory_counters.last_value + 1
        RETURNING last_value
    """, (prefix, year, specialty_code)).scalar()
    return f"{prefix}-{year}-{specialty_code}-{seq:05d}"
```

**Правила:** номер присваивается один раз и не переиспользуется даже после списания. При переводе актива в другое отделение номер **не меняется** — он отражает специальность на момент постановки на учёт, а не текущее размещение (иначе рушится история). Номер уникален глобально.
