Применение миграций ver. 9.23: исключения из состава открытой линии и путь
сообщения по каскаду в журнале рассылки.

Из папки backend, ДО перезапуска портала и отправщика уведомлений. Без
таблицы не откроются настройки линий в админке и пересчёт состава по правилам,
без колонки attempts — встанет вся очередь уведомлений, включая заведение
новых:

  npm run migrate:9.23:check     посмотреть, чего ещё нет
  npm run migrate:9.23           применить

Создаёт таблицу omni_line_exclusions, колонку omni_lines."autoCloseHours"
(автозакрытие обращений после тишины, по умолчанию 8 часов на всех линиях —
включается сразу) и колонку notif_outbox.attempts (путь по
каскаду; без неё не отправит ни одно сообщение — отправщик пишет её при каждой
отправке, поэтому миграция и до перезапуска отправщика тоже).

Таблица omni_line_exclusions: исключений после миграции нет, состав
линий не меняется. Исключают в «Открытая линия и оповещения» → «Линии» →
состав линии: у сотрудника, заведённого правилом, кнопка снятия теперь
исключает его. Вернуть — в блоке «Исключены» той же линии.

Кто исключён:

  SELECT l.name AS линия, u."displayName" AS сотрудник
  FROM omni_line_exclusions e
  JOIN omni_lines l ON l.id = e."lineId"
  JOIN users u ON u.id = e."userId"
  ORDER BY 1, 2;
