Применение миграции ver. 8.42 (привязка задачи к команде).

ПЕРЕД ЗАПУСКОМ СДЕЛАЙТЕ РЕЗЕРВНУЮ КОПИЮ БАЗЫ. Из папки backend:

  npm run backup

Затем:

  npm run migrate:8.42:check     посмотреть план
  npm run migrate:8.42           применить

Что делает. Добавляет в таблицу tasks колонку teamId со ссылкой на task_teams и
индекс по ней. Ничего не удаляет и ничего не переписывает: у всех существующих
задач teamId остаётся пустым.

Что это значит для людей. Появляется различие между личной и командной задачей.
Личная — как раньше: её видят автор, исполнители и руководитель над
исполнителем. Командная — открыта всему составу команды целиком, вместе с
описанием и вложениями; наблюдатель (viewer) тоже видит её полностью, но
изменить в ней ничего не может.

Все задачи, заведённые до этого релиза, остаются личными. Раздавать их по
командам задним числом мы не стали намеренно: это открыло бы участникам
переписку и файлы за всё время работы модуля, о чём их никто не предупреждал.
Привязать задачу к команде можно вручную в её карточке — это делает автор или
руководитель команды.

Что сделать после выката: перезапустить бэкенд.
