Применение миграции ver. 8.03 (почва под раздельные филиалы).

Из папки backend:

  npm run migrate:8.03:check     посмотреть, чего ещё нет
  npm run migrate:8.03           применить

Миграция идемпотентна: всё через IF NOT EXISTS, перенос smsText делается только
там, где channelTexts ещё пуст.

ЧТО ПОЯВЛЯЕТСЯ. Три вещи, и все три необязательные — пусто означает «как было»,
поэтому сразу после миграции ничего не меняется.

  1. notif_templates."channelTexts" — свой текст на каждый канал (telegram, max,
     sms). Прежний smsText переезжает в ключ sms автоматически. Колонка smsText
     остаётся на месте намеренно: отправщик в tmux перезапускают руками, и до
     перезапуска он должен продолжать работать по-старому.

  2. notif_templates.cascade — свой порядок ступеней у события. NULL означает
     «идти общим каскадом». Заводилось ради просьбы об отзыве: по SMS её не
     выполнить, кнопок там нет, а деньги списываются.

  3. notif_branch_settings — отличия филиала от общих настроек: свой каскад,
     свои тихие часы, своё имя отправителя у Имобиса, признак «филиал включён».
     Филиал, которому нечего переопределять, строки в этой таблице не имеет.

ПОРЯДОК ПЕРЕЕЗДА ФИЛИАЛОВ. Подключать по одному, а не все разом:

  • завести филиалу строку настроек и снять «филиал включён» у остальных;
  • у включённого филиала снять в МИС галки «Отправлять сообщение» — иначе
    пациент получит два уведомления об одном событии;
  • убедиться по журналу, что уходит именно наше, и только потом брать
    следующий филиал.

ПОСЛЕ ЗАПУСКА перезапустить отправщик (окно tmux с notifier): без перезапуска он
продолжит слать один текст на все каналы и общий каскад на все события.

Отката нет намеренно: колонки добавляются, ничего не удаляется, и старый код с
новой схемой работает.
