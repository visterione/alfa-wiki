Применение миграции ver. 8.55 (площадка Plaso.pro отключена).

ПЕРЕД ЗАПУСКОМ СДЕЛАЙТЕ РЕЗЕРВНУЮ КОПИЮ БАЗЫ. Из папки backend:

  npm run backup

Затем:

  npm run migrate:8.55           применить

Проверки --check у этой миграции нет по существу: она ничего не создаёт, а
удаляет, и runSqlMigration в таком случае честно отвечает «проверять нечего».
Посмотреть, сколько отзывов уйдёт, можно заранее одним запросом:

  SELECT count(*) FROM reviews
   WHERE "platformId" IN (SELECT id FROM review_platforms WHERE name = 'Plaso.pro');

Что делает. Удаляет физически все отзывы площадки Plaso.pro вместе с их
историей обработки, а затем и саму строку площадки из справочника. Отменить
нельзя — только восстановлением базы из копии.

Что уже сделано в коде этого релиза. Адаптер GetLoyalty не берёт источники с
identity = plasopro: их source_hash_key не попадает в фильтр филиала, и отзывы
отсеиваются там же, где отзывы чужих филиалов. Новых записей не появится и без
миграции — она нужна для того, что уже накоплено.

Почему площадка убрана. Отзывы оттуда к сети почти не относятся: агрегатор
отдаёт чужие карточки. Обработчик разбирал их наравне с настоящими, а разрез
статистики по площадкам считал их нашими. Ответить на такой отзыв через
GetLoyalty всё равно было нельзя.

Что миграция не трогает. Файлы, приложенные к удалённым отзывам, остаются в
backend/uploads/reviews — они лежат помесячно, вперемешку с файлами живых
отзывов, и выбрать оттуда «те самые» нечем. Места они занимают немного:
приложения к автоимпортированным отзывам — редкость.

Что сделать после выката: перезапустить бэкенд.

Чего ждать людям. Plaso.pro пропадёт из фильтра площадок на доске и в архиве, из
разреза по площадкам в статистике и из списка площадок в «Проверить
подключение» у синхронизации. Счётчики отзывов и доля негатива пересчитаются
сами — на величину удалённого архива, то есть станут меньше и точнее.
