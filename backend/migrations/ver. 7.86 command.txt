Применение миграции ver. 7.86 (уведомления пациентам).

Из папки backend:

  npm run migrate:7.86:check     посмотреть, чего ещё нет
  npm run migrate:7.86           применить

Миграция идемпотентна. Шаблоны по умолчанию заводятся только если таблица
пустая — повторный запуск не затрёт тексты, поправленные заказчиком.

Проверка без отправки (один проход, покажет что нашлось):

  npm run notifier:once

Боевой режим — отдельным окном tmux, рядом с забором обновлений ботов:

  until npm run notifier; do echo "упал, поднимаю через 5 с"; sleep 5; done

Первый запуск намеренно НЕ выгребает историю: водяного знака ещё нет, и
детектор начинает с текущей минуты. Иначе людям прилетели бы напоминания о
визитах годичной давности.

ПРЕДОХРАНИТЕЛИ. Детектор видит изменения по всей сети, а не только по пилотной
клинике, поэтому по умолчанию:

  • вторая ступень каскада (Fromni: Notify, ВК, SMS) ВЫКЛЮЧЕНА — уведомления
    уходят только подписчикам наших ботов. Включается осознанно:
        NOTIFIER_ALLOW_FROMNI=true
  • круг получателей можно сузить до списка телефонов:
        NOTIFIER_PILOT_PHONES=+79990000000,+79991111111
    Остальное помечается «skipped» с причиной — видно в notif_outbox.

Снимать их можно только вместе со снятием галок «Отправлять сообщение» в МИС у
той же организации. Иначе пациент получит два уведомления об одном событии.

Пока не заполнено соответствие клиник организациям (настройка notif_clinic_org),
вторая ступень уходит во Fromni под аккаунтом из FROMNI_DEFAULT_ORG (по
умолчанию alfa).
