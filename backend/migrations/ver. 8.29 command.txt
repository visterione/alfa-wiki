Применение миграции ver. 8.29 (темы обращений открытой линии).

Из папки backend:

  npm run migrate:8.29:check     посмотреть план
  npm run migrate:8.29           применить

Что делает. Заводит справочник omni_topics и колонку omni_sessions."topicId" —
о чём было обращение. Тема ставится обращению, а не переписке: у постоянного
пациента переписка вечная и за год вмещает и запись, и анализы, и жалобу.

Засев. В пустой справочник добавляются десять тем по ожидаемой частоте: запись,
перенос, цены, анализы, врачи, режим работы, подготовка к исследованию,
документы, жалоба, другое. Список не окончательный — старший оператор линии
правит его прямо в рабочем окне, там же, где быстрые ответы.

Почему засев вообще есть: без единой темы выбирать при закрытии не из чего, и
обязательность выбора пришлось бы отключать в день выката.

Миграция идемпотентна: таблица и колонка создаются с IF NOT EXISTS, засев идёт
только в пустой справочник. Повторный запуск безвреден.

Что НЕ делает. Закрытые ранее обращения остаются без темы — проставить её задним
числом нечем, а угадывать по тексту переписки хуже, чем показать пробел честно.
В отчёте они собраны строкой «без темы».
