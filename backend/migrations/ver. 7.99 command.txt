Применение миграции ver. 7.99 (открытая линия: вечная переписка, обращения,
смены, оценки).

Из папки backend:

  npm run migrate:7.99:check     посмотреть, чего ещё нет
  npm run migrate:7.99           применить

Миграция идемпотентна по объектам (таблицы, колонки, индексы), но перенос данных
одноразовый по своей природе: после слияния переписки одного собеседника уже
слиты, и второй запуск просто ничего не найдёт.

ЧТО ПРОИСХОДИТ С ДАННЫМИ. У каждого собеседника было столько переписок, сколько
раз он обращался. Они сливаются в одну — выживает открытая, а если все закрыты,
самая свежая; сообщения и обращения переезжают к ней, лишние строки
omni_conversations удаляются. Каждая прежняя переписка становится обращением
(omni_sessions), поэтому архив не теряется: в ленте он показан разделителями.

ПЕРЕД ЗАПУСКОМ имеет смысл посмотреть, сколько строк схлопнется:

  SELECT COUNT(*) - COUNT(DISTINCT "subscriberId") AS "лишних переписок"
  FROM omni_conversations;

ПОСЛЕ ЗАПУСКА перезапустить забор обновлений (окно tmux с messengerPoller):
git pull его не обновляет, а логика приёма входящих изменилась — иначе входящие
продолжат заводить обращения по старым правилам.

Оценка работы оператора приходит пациенту кнопками 1–5 сразу после закрытия
обращения и только если сотрудник успел ответить: спрашивать «как вам наша
работа» после молчания незачем. Рейтинг и KPI — вкладка «Показатели» в модуле.
