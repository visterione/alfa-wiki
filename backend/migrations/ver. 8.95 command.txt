Применение миграции ver. 8.95 (ИИ-звонки: настоящий API партнёра и итог звонка).

ПЕРЕД ЗАПУСКОМ СДЕЛАЙТЕ РЕЗЕРВНУЮ КОПИЮ БАЗЫ. Из папки backend:

  npm run backup

Затем:

  npm run migrate:8.95:check     посмотреть план
  npm run migrate:8.95           применить

Что делает.

  settings.notif_ai_call                 — новая строка: доступ к CRM партнёра,
                                           общий на сеть. Проект и шаг воронки
                                           вписаны сразу, логин и пароль — нет;
  notif_branch_settings.ai_call          — прежние адрес, ключ и имя заголовка
                                           стираются, остаётся включатель;
  notif_call_requests                    — семь колонок: лид и контакт у партнёра,
                                           итог звонка, когда он получен, тело
                                           присланного, что вышло в МИС и почему
                                           не вышло;
  notif_outbox.event                     — правит метку у накопившихся
                                           напоминаний (см. ниже).

ПОЧЕМУ ПРАВИТСЯ notif_outbox.event. Строка очереди получала событие повода, а не
своё: запись ставит попутно напоминания, и они оказывались помеченными как
«запись». В журнале напоминание подписывалось чужим именем, фильтр по событию его
не находил, каскад брался от записи — а догоняющий ИИ-звонок не заводился вовсе,
потому что спрашивает ровно про «reminder». То есть звонки не работали с самого
8.52, и выяснилось это на первом живом прогоне. Причина исправлена в коде
(detector.js и templates.build), а миграция переставляет метку у тех строк,
которые уже лежат в очереди; отличить их можно точно по ключу идемпотентности.

Что это значит для людей.

В 8.52 догоняющий звонок выкатили без спецификации партнёра: формат лида был наш
собственный, а адрес и ключ вписывались в карточке каждого филиала. Теперь партнёр
известен — LPTracker, — и выяснилось главное: проект у него уже подготовлен под
наши визиты. В нём заведены поля appointment_id, patient_name, time_start,
clinic_title, doctor_name, mobile и шаги воронки «Обзвон роботом», «Подтвердил»,
«Отменил», «AI · Не дозвонились». Портал заполняет эти поля, сопоставляя их по
имени, и кладёт лид на шаг «Обзвон роботом».

Появился обратный путь, которого раньше не было. По итогу разговора CRM вызывает
наш метод, и портал ставит отметку в МИС — теми же двумя способами, какими её
ставит кнопка в боте. «Подтвердил» подтверждает визит, «отменил» отменяет с
пометкой, что отмена сделана пациентом в разговоре с роботом. Остальные исходы —
не дозвонились, автоответчик, «перезвоните позже» — записываются в журнал и видны
в заявке словами. Без этого звонок ничего не менял: визит оставался активным, и о
неявке узнавали в день приёма.

ПОЧЕМУ ДОСТУП СТАЛ ОБЩИМ НА СЕТЬ. В 8.52 он лёг на филиал — вслед за счётом
Имобиса, у которого на каждое юрлицо свой лицевой. У партнёра иначе: проект один
на всю сеть, клиника визита уезжает полем clinic_title. Шесть копий одного пароля
по карточкам филиалов означали бы шесть мест, где его забудут поменять. У филиала
остались включатель и необязательные «свой проект» и «свой шаг воронки» — на
случай, если партнёр когда-нибудь разведёт клиники по проектам.

Что сделать после применения миграции. Звонки не включаются сами: логин и пароль
не заданы, а предохранитель «CRM партнёра (ИИ-звонки)» стоит.

  1. Администрирование → Открытая линия → Рассылка → «CRM для ИИ-звонков»:
     вписать логин и пароль, нажать «Проверить». Проверка войдёт в CRM, покажет
     проекты и шаги воронки списком и скажет, какие из наших полей нашлись в
     проекте. Проект «Медцентр Альфа» и шаг «Обзвон роботом» уже выбраны.
  2. Там же, в карточке каждого филиала → «ИИ-звонки молчунам» → тумблер
     «передавать заявки».
  3. Вкладка «Тексты» → событие «Напоминание о визите» → галка «Позвонить, если
     не ответил», а под ней два срока: «Позвонить через» и «Не звонить позже чем
     за». Оба поля появляются только при включённой кнопке «Подтверждаю».
  4. Вкладка «Рассылка» → предохранитель «CRM партнёра (ИИ-звонки)».

Порог «не звонить позже чем за» проставьте осознанно. Он существует затем, что
срок отсчитывается от отправки напоминания, а не от визита: при напоминании за два
часа и сроке в три часа звонок пришёлся бы на время приёма.

Ключ для партнёра выдаётся отдельно: Администрирование → Интеграции → создать
ключ с правом «CRM партнёра: итоги ИИ-звонков пациентам». Этим ключом визиты
отменяются в МИС — задайте ему список IP партнёра. Описание обмена для их
программиста — PUBLIC_API_AI_CALL.md в корне репозитория.

Проверить, что происходит, из папки backend:

  npm run notifier:calls        последние заявки, итоги звонков и отметки в МИС

Что сделать после выката: перезапустить бэкенд и notifier.
