Применение миграции ver. 8.02 (ширина channel в журнале отправок).

Из папки backend:

  npm run migrate:8.02:check     посмотреть, что уже на месте
  npm run migrate:8.02           применить

ЧТО ЧИНИТ. Колонка notif_outbox.channel была VARCHAR(20), а отправка с 7.94
пишет туда весь маршрут каскада через «→»: «notify+vk→sms+webchat» — это уже
21 символ, «imobis:vk→imobis:viber→imobis:sms» — 33. Postgres такую запись
отклоняет, и падает не отправка, а обновление строки после неё: сообщение
пациенту ушло, а в очереди осталось «pending». Следующий проход отправлял его
ещё раз, и так по кругу.

На бою это не проявлялось только потому, что вторая ступень каскада выключена
предохранителем NOTIFIER_ALLOW_FROMNI — до Fromni дело не доходило, а имена
наших ботов («telegram», «max») в двадцать символов помещаются. Снимать
предохранитель БЕЗ этой миграции нельзя.

Проверить, есть ли уже пострадавшие строки (должно быть пусто):

  SELECT id, event, phone, planned_at
    FROM notif_outbox
   WHERE status = 'pending' AND planned_at < NOW() - interval '1 hour';

Отката нет намеренно: расширение типа обратно не сужают, а данных миграция не
трогает.
