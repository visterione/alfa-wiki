Применение миграции ver. 8.10 (старший оператор линии).

Из папки backend:

  npm run migrate:8.10:check     посмотреть, чего ещё нет
  npm run migrate:8.10           применить

Добавляет одну колонку: omni_line_operators."isSenior", по умолчанию false.

ВАЖНО СРАЗУ ПОСЛЕ ЗАПУСКА. Архив закрытых обращений пропадает у всех — вкладки
«Архив» в открытой линии больше не видно ни у кого, пока не назначены старшие.
Это и есть смысл изменения, но пользовавшихся архивом надо назначить, иначе они
придут с вопросом.

  «Открытая линия и оповещения» → «Линии» → в блоке «Состав» звёздочка у
  сотрудника. Звёздочка горит жёлтым — он старший на этой линии.

Старшинство привязано к линии, а не к человеку: старший в своём филиале
остаётся рядовым оператором в соседнем и архив соседнего не увидит.

Проверить, кто назначен:

  SELECT l.name AS линия, u."displayName" AS сотрудник
  FROM omni_line_operators o
  JOIN omni_lines l ON l.id = o."lineId"
  JOIN users u ON u.id = o."userId"
  WHERE o."isSenior"
  ORDER BY 1, 2;

ОСОБОГО ХОДА ДЛЯ АДМИНИСТРАТОРОВ НЕТ. Открытая линия и так открывается только
тому, кто заведён в состав линии, и архив внутри неё подчиняется тому же
правилу: нужен архив — поставьте себе звёздочку в составе. Отдельный обход по
признаку администратора не заводили намеренно, чтобы право на чтение чужих
переписок было видно в одном месте — в составе линии.
