Применение миграции ver. 8.51 (Notify переезжает на прямой канал Имобиса).

ЭТА МИГРАЦИЯ ОБЯЗАТЕЛЬНА ВМЕСТЕ С РЕЛИЗОМ. Ступени «Notify через Fromni» в
выборе больше нет, и каскад, в котором она ещё записана, окажется со ступенью,
которую интерфейс не знает: в списке она покажется голым именем «notify+vk», без
поля текста. Выкатили код — применяйте миграцию.

ПЕРЕД ЗАПУСКОМ СДЕЛАЙТЕ РЕЗЕРВНУЮ КОПИЮ БАЗЫ. Из папки backend:

  npm run backup

Затем:

  npm run migrate:8.51:check     посмотреть план
  npm run migrate:8.51           применить

Что делает. Колонок не трогает. Заменяет имя ступени «notify+vk» (Fromni) на
«imobis:vk» (прямой канал) в сохранённых каскадах — общем по сети, у филиалов и
у отдельных событий — и в тихих часах. Порядок ступеней сохраняется.

ПОЧЕМУ ПЕРЕЕЗД. Каналом Notify всегда был Имобис. В подключении, которое
заводилось во Fromni, вводились три вещи: название подключения, токен доступа к
API Имобиса и ссылка на группу ВКонтакте. То есть Fromni брала наш запрос и
пересылала его туда же, куда мы теперь ходим сами. Посредник стоил того же,
чего стоил у SMS (см. 8.50): исход отправки Fromni не сообщает — отвечает
«принято», а отчёт о доставке уходит на её сервер. У Имобиса отчёт приходит нам,
и в журнале видно, дошло ли уведомление, а не только что его приняли.

Вместе с 8.50 это значит, что каскад к Fromni не ходит больше ни за чем.

ЧТО ЗАПОЛНИТЬ У КАЖДОГО ФИЛИАЛА (Администрирование → Открытая линия → Филиалы).

1. Токен Имобиса — тот же, что вводился в подключении Fromni. Если SMS у
   филиала уже работает, это он и есть.

2. Группа ВК — теперь просто СКОПИРУЙТЕ ССЫЛКУ, как во Fromni:
   https://vk.com/3k_anapa. Поле было числовым, стало обычным; ссылка,
   короткий адрес и старый числовой id понимаются одинаково, а уже вписанные
   числа продолжают работать без правок.

3. Нажмите «Проверить счёт». Кроме баланса и имён отправителя показываются
   шаблоны аккаунта. Для ВК-канала это главное: сообщение в ВКонтакте уходит
   только по одобренному шаблону. «Шаблонов нет» — значит Notify у этого
   филиала не пойдёт, сколько ни заполняй остальное; шаблоны заводятся и
   проходят модерацию на стороне Имобиса, порталом их не создать.

4. Отправьте тестовое сообщение по ступени «Notify» на свой номер и посмотрите
   журнал: строка должна дойти до «доставлено», а не остаться в «принято».

ЧЕГО МЫ НЕ ЗНАЕМ ЗАРАНЕЕ. Принимает ли Имобис короткий адрес группы вместо
числового id — по их документации у нас ответа нет. Если ссылка содержит число
(vk.com/club123456789), мы отдаём число и вопрос не встаёт. Для короткого адреса
отдаём адрес как есть; откажет — это будет видно в журнале полным текстом ответа
их API, и тогда в поле нужно вписать числовой id. Проверяется это пунктом 4
за одну отправку.

ЗАПАСНОЙ ПУТЬ НА ВРЕМЯ ПЕРЕХОДА. Если в каскаде филиала за Notify стоит SMS,
обе ступени уходят в Имобис одним запросом с общим маршрутом: не прошёл ВК —
провайдер сам возьмёт следующую ступень. У филиала, где после ботов стоит
только Notify, такой подстраховки нет — до проверки по пункту 4 лучше держать
SMS следом.

Журнала это не касается: строки с «notify+vk» остаются как есть — так и было
отправлено, расшифровка имени в отчётах оставлена на месте.

Что сделать после выката: перезапустить бэкенд.
