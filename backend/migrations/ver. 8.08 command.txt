Применение миграции ver. 8.08 (категория подписчика в МИС у бота).

Из папки backend:

  npm run migrate:8.08:check     посмотреть, чего ещё нет
  npm run migrate:8.08           применить

Миграция идемпотентна и ничего не переносит: у messenger_bots появляется одна
пустая колонка "misCategoryId". Пока она пуста, поведение прежнее — бот никого
не помечает.

ПЕРЕНОСИТЬ ИЗ .env НЕЧЕГО. MIS_CATEGORY_TELEGRAM и MIS_CATEGORY_MAX стоят
пустыми с 7.84, то есть ни одна подписка так и не была помечена в МИС. Обе
переменные больше не читаются и из .env их можно убрать.

ЧТО СДЕЛАТЬ ПОСЛЕ ЗАПУСКА

  1. Открыть «Открытая линия и оповещения» → вкладка «Рассылка», раскрыть
     филиал. В строке бота появилось поле «категория МИС» — вписать туда номер
     категории, заведённой в МИС именно под этого бота, и нажать Enter.

  2. Проверить на себе: написать боту /start и поделиться контактом. В карточке
     пациента в МИС должна появиться категория, у подписчика — статус tagged:

       SELECT platform, organization, status, "taggedAt" FROM bot_subscribers
       WHERE phone = '7XXXXXXXXXX';

ПОЧЕМУ ЭТО ЗАМЕТНО НЕ ТОЛЬКО В МИС. Вкладка «Боты» считает подписки по
status = 'tagged'. Пока категорий не было, свои боты давали в этой статистике
ноль независимо от того, сколько человек к ним пришло. С заполненной категорией
счётчик начнёт расти — но только по новым подпискам.

УЖЕ ПОДПИСАННЫЕ ОСТАЮТСЯ БЕЗ КАТЕГОРИИ. Пометка ставится в момент, когда человек
делится номером, задним числом никто по базе не проходит. Тем, кто подписался
раньше, категория проставится сама, когда они в следующий раз напишут боту, —
обращения в открытую линию догоняют пометку. Если этого мало и категории нужны
всем сразу, нужен отдельный проход по bot_subscribers; он не написан.
