Применение миграции ver. 9.34 (журнал рассылки: порядок каскада и отказы провайдера).

Из папки backend, ПОСЛЕ перезапуска портала и процесса отправки (новый код
уже пишет путь в порядке каскада и переводит отказы в «не доставлено»; скрипт
чинит только строки, записанные до этого):

  npm run migrate:9.34:check     сколько строк будет исправлено, ничего не меняя
  npm run migrate:9.34           исправить

Что делает:
  1. Переставляет путь по каскаду в порядке каскада события и медцентра —
     раньше выпавшая из маршрута ступень (Notify без группы ВК) ложилась в
     путь раньше переданных, и «SMS → Notify» выглядело как «Notify → SMS».
  2. Строки, где последний отчёт провайдера — отказ, переводит из «Доставлено»
     в «Не доставлено».

Запускать один раз и сразу: путь выстраивается по каскаду, настроенному
сейчас. Если каскад потом поменяют, повторный запуск старых строк уже не
тронет — у них ступени не совпадут с новым каскадом либо порядок уже верный.
