Применение миграции ver. 8.09 (передача чата, файлы от оператора, быстрые ответы).

Из папки backend:

  npm run migrate:8.09:check     посмотреть, чего ещё нет
  npm run migrate:8.09           применить

Миграция идемпотентна. Что делает:

  1. bot_subscribers."patientMisId" — чья карточка выбрана из patientIds.
     Заполняется задним числом по номеру карты через справочник mis_patients,
     поэтому зелёная кнопка «R» в шапке чата появится сразу, а не после
     обновления снимка (оно раз в двенадцать часов и только при новом
     сообщении). У кого номера карты нет — не появится и кнопка: это те, кого в
     МИС не нашли.

  2. omni_quick_replies — быстрые ответы. Таблица создаётся пустой; заготовки
     заводят сами операторы кнопкой «молния» в поле ответа, администратор для
     этого не нужен.

ЧТО ПРОВЕРИТЬ ПОСЛЕ ЗАПУСКА

  Сколько подписчиков получили ссылку на карточку:

    SELECT count(*) FILTER (WHERE "patientMisId" IS NOT NULL) AS "со ссылкой",
           count(*) FILTER (WHERE "patientCard" IS NOT NULL) AS "с картой"
    FROM bot_subscribers;

  Числа должны почти совпасть. Заметная разница означает, что справочник
  mis_patients отстал: он пополняется отдельной выгрузкой, и карточки, заведённые
  после последней, в нём ещё не значатся. Само дозаполнится при обновлении
  снимка.

ФАЙЛЫ ОТ ОПЕРАТОРА ложатся туда же, где лежат присланные пациентом, —
backend/uploads/open-line/<id переписки>/. Отдельного каталога и отдельной
проверки доступа не заводили: файл в переписке принадлежит переписке, кто бы его
ни отправил.
