# Исправление кодировки имен файлов аккредитаций

## Проблема
Имена файлов с русскими символами отображаются как "Ð ÐµÐ·ÑÐ»ÑÑÐ°ÑÑ..." вместо "Результаты..."

## Причина
Multer получает имена файлов в кодировке latin1, а мы сохраняли их в базу как есть, без конвертации в UTF-8.

## Решение

### 1. Перезапустить сервер
Были внесены изменения в код:
- `backend/routes/accreditations.js` - добавлена конвертация кодировки при загрузке файлов
- `backend/bot/accreditations.html` - улучшен парсинг имени файла при скачивании
- `backend/models/index.js` - убраны неправильные настройки charset для PostgreSQL

```bash
cd backend
npm run dev
```

### 2. Исправить существующие записи в БД (если есть файлы с неправильной кодировкой)
```bash
cd backend
node scripts/fixAccreditationFilesEncoding.js
```

Скрипт найдет все файлы с неправильной кодировкой и автоматически исправит их имена.

### 3. Проверка
После выполнения:
1. Откройте страницу аккредитаций
2. Нажмите кнопку "Файлы" на любой записи
3. Загрузите новый файл с русским именем
4. Убедитесь, что имя отображается корректно
5. Скачайте файл - имя должно остаться правильным

## Что было исправлено

### Backend (routes/accreditations.js)
```javascript
// Было:
originalName: file.originalname,

// Стало:
const originalName = Buffer.from(file.originalname, 'latin1').toString('utf8');
```

### Frontend (bot/accreditations.html)
Улучшен парсинг заголовка `Content-Disposition` для корректного извлечения имени файла при скачивании.

### Database (models/index.js)
Убраны некорректные настройки charset для PostgreSQL (они нужны только для MySQL).

## Результат
- ✅ Новые файлы сохраняются с правильной кодировкой
- ✅ Имена файлов корректно отображаются в модальном окне
- ✅ При скачивании файл получает правильное русское имя
- ✅ Существующие файлы можно исправить скриптом миграции
